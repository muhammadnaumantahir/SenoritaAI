# Glossary

- **SPS:** Self-Programming Software; software that understands, develops, verifies and evolves its own capabilities.
- **Autonomous operation:** execution of pre-authorised tasks without a per-task user prompt.
- **Evolution cycle:** observe, diagnose, propose, research, build/absorb, verify, release, monitor and learn.
- **Absorption:** acquisition and integration of useful external software capability.
- **Source absorption:** selective reuse/adaptation of actual source code under its licence.
- **Component absorption:** adoption of an external package or component as a dependency.
- **Knowledge absorption:** learning a technique and implementing an independent solution.
- **Trusted supervisor:** foundation responsible for policy, lifecycle, monitoring and recovery.
- **Evolutionary module:** module that may be modified through controlled evolution.
- **Capability contract:** versioned declaration of a capability's purpose, interfaces, dependencies, permissions and tests.
- **Provenance:** traceable record of where code came from and how it was modified.
- **SBOM:** Software Bill of Materials, an inventory of components and dependencies in a release.
- **Safe mode:** restricted state entered when integrity or recovery confidence is low.
- **Rollback:** return to a known-good release/configuration after a failed change.
- **Policy gate:** deterministic control that permits, denies or holds an action.
- **Canary release:** limited deployment used to validate health before wider promotion.
