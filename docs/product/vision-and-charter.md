# Vision and Charter

## Vision
Build Senorita as a Self-Programming Software (SPS) ecosystem: a long-running system that understands itself, discovers opportunities, acquires useful capabilities, develops improvements, verifies them and evolves without needing a user to direct every individual cycle.

## Core promise
After installation and initial policy configuration, Senorita should independently maintain an improvement backlog and execute safe, useful work. User involvement should be exceptional, not a prerequisite for every research, development, testing or maintenance task.

## Principles
1. Autonomy by default within explicit permission and resource limits.
2. Native capabilities over a dashboard that merely connects separate products.
3. Absorb source code only when legal rights and licence obligations permit it.
4. Learn techniques and independently implement them when direct reuse is unsuitable.
5. Treat generated code and repository content as untrusted until verified.
6. Keep a stable recovery supervisor outside ordinary self-modification.
7. Make every change traceable, testable, reversible and documented.
8. Prefer small, measurable improvements over opaque rewrites.

## Reality constraints
Autonomy does not guarantee perpetual uptime. Power, hardware, storage, operating-system health, network access, model availability, licences and external services remain dependencies. High-impact or irreversible actions require strict gates or explicit approval.

## Non-goals
- Merely installing popular GitHub projects and connecting their dashboards.
- Unrestricted administrator access for AI agents.
- Blind copying of popular repositories.
- Claiming complete autonomy before long-duration reliability evidence exists.
